# 도로 우선 도시계획용 메시 제작 요청서

2026-10-22. 이 문서는 모델링 에이전트에게 전달할 제작 명세다. 게임의 교통 그래프와 임시 도로 형상을 먼저 정하고, 최종 메시가 같은 차선 수·접속 위치·높이를 따르도록 한다. 현재 도로는 `SimpleGame/Overworld.cpp`의 `RoadNetwork`와 `SimpleGame/TransitLayout.cpp`의 절차적 `DraftRoad_*`·`DraftJunction_*` 평면 메시로 표시한다. 기존 고해상도 도로 조립체를 억지로 늘리거나 겹쳐서 도시 배치를 결정하지 않는다.

## 1. 계획 기준과 현재 적용 범위

- **도로 위계:** 헤일로·신더·에코의 집산도로는 왕복 4차선, 베일·서쪽 도시 및 생활도로·도시 간 도로는 왕복 2차선이다. 현 계획에는 왕복 6차선 이상의 지상 도로가 없다.
- **교차로:** 집산도로는 4+4+2차선 T자 교차로로 연결한다. 한 교차로로 들어오는 모든 가지의 왕복 차선 수 합은 최대 10이다. 생활도로는 2+2+2 T자 또는 2+2+2+2 사거리다. 5갈래 이상 교차로와 4차선 도로 두 개가 교차하는 대형 사거리는 만들지 않는다.
- **연결성:** 각 도시의 집산도로는 로컬 좌표 `(-90,-17)→(60,-17)`을 잇는다. 생활도로는 X=-32·30, Y=10·32 부근의 작은 고리와 연결로로 구성한다. 건물은 도로 가장자리에서 물러난 필지에 배치하고, 건물 출입구를 보행로에 연결한다. 도시의 중심과 도시 간 경로가 동일한 거대 교차로로 집중되지 않도록 출입점을 분산한다.
- **입체 교차:** 헤일로 동쪽 X=48에 남북 고가 우회로를 두고, Y=-17의 동서 집산도로와 연결 없는 입체 교차를 만든다. 두 층의 교통 그래프·차량 고도는 분리한다. 같은 평면 좌표라고 도로 포트를 합치지 않는다.
- **현재 임시 고가:** 월드 `(48,-100,0)→(48,-45,4)` 진입 램프, `(48,-45,4)→(48,45,4)` 상부, `(48,45,4)→(48,100,0)` 진출 램프다. 램프 한쪽의 수평 길이는 110m, 높이 변화는 8m다. 실제 포트 간 유효 경사도는 9% 이하여야 한다.
- **순서:** 도로·보행 연결·층간 여유 → 건물 필지 → 출입구·퀘스트 접근 → 주민·차량 → 장식 순서로 검토한다. 장식이 접속면이나 대기 공간을 차지하지 않게 한다.

교차로를 작게 나누고 복잡한 한 지점의 충돌을 줄이는 방향은 [NACTO의 교차로 설계 원칙](https://nacto.org/publication/urban-street-design-guide/intersections/intersection-design-principles/)을 참고했다. 연결된 가로망을 토지 이용과 보행의 뼈대로 삼는 방향은 [CNU의 Street Networks](https://www.cnu.org/our-projects/street-networks)를 참고했다. 아래 수치와 SF 표현은 게임을 위한 설계 선택이며, 두 자료가 이 게임의 치수를 규정하는 것은 아니다.

## 2. 단위·축·접속 계약

| 항목 | 계약 |
|---|---|
| 원본 단위 | 미터, 적용된 양의 스케일 1 |
| 게임 변환 | **1월드 단위=2m**, 메시와 포트 위치를 동일하게 0.5배 |
| 제작 좌표 | Blender +Z 위, 직선 진행 축 +X |
| GLB 변환 | `(x,y,z)→(x,z,-y)`, 기존 내보내기 파이프라인 유지 |
| 차선 | 1차선 3m. 왕복 2차선 6m, 왕복 4차선 12m. 보도·연석 폭 제외 |
| 보도 | 기본 유효 폭 2m, 별도 모듈. 명목 표면 Z=0.15m |
| 명목 노면 | 모듈 기준 Z=0. 보도·표식·연석의 높이는 같은 기준면에서 정의 |
| 포트 정보 | `id`, `kind`, `position_m`, `outward`, `width_m`, `lanes`, `level`, 필요 시 `slope` |
| 결합 | 같은 종류·폭·차선 수·높이의 포트를 위치 일치, outward 반대 방향으로 접속 |
| 금지 | 원점 재중앙화, 음수 스케일, 차선 폭 늘이기, 도로 겹쳐 가짜 교차로 만들기 |

현재 임시 도로는 지면과 겹치지 않도록 상면 약 0.05m, 임시 보도는 약 0.15m에 놓는다. 이 오프셋을 최종 원본에 중복해서 굽지 않는다. 최종 메시 전환 때 게임 배치 높이와 명목 노면/보도 기준을 함께 맞춘다. 페인트와 홀로그램은 노면에서 수 mm 수준으로 분리하며 별도 두꺼운 도로 판을 포함하지 않는다.

직선의 원점은 구간 중앙이다. T/사거리의 원점은 교차 중심이다. 곡선은 진입 중심선 포트가 원점이고 진입 방향은 +X다. 램프는 하단 중앙 포트가 원점이다. 부품은 조립체의 공통 원점을 유지한다. 부품마다 임의로 중심을 다시 잡지 않는다.

## 4. 고가의 높이와 미구현 범위

현재 상부 노면 높이는 약 8m이며, 임시 메시는 두께 없는 상면이다. **교량 하부 유효 높이 8m를 이미 확보한 상태라는 뜻이 아니다.** 최종 구조에서 지상 통행 공간 위 최소 8m를 비우려면 거더·데크 두께까지 포함해 상부 노면 높이를 올려야 한다. 예를 들어 하부 구조 두께가 0.4m이면 노면 기준 높이는 최소 8.4m가 필요하다. 이 경우 램프 끝 포트 높이와 실제 경사를 게임 코드와 함께 수정한다. 110m 수평 길이에서 8.4m 상승은 평균 약 7.64%지만, 종단곡선·교차로 절삭 뒤의 **최대** 경사를 별도로 검사한다.

현재 프로토타입에는 정교한 교각·지하차도·터널이 없고, 고가 난간도 단순한 높이 표시 띠다. 최종 난간 충돌·교각 충돌·건축 한계·램프 아래 낮은 공간의 보행 금지·층별 가림 검사는 메시 납품만으로 자동 완성되지 않는다. 아트 에이전트는 필요한 충돌/여유공간 메타데이터를 제공하고, 게임 에이전트가 연결한다.

램프 하부는 높이가 낮은 구간과 통과 가능한 구간을 구분한 clearance envelope를 제공한다. 상부 전체 아래에 건물이나 보행로를 놓아도 된다는 가정을 하지 않는다. 지상 도로와 교차하는 상부 구간에는 교각을 두지 않는다.

## 5. 기능 파트·재질·제작 방식

반드시 [Resource/AGENTS.md](Resource/AGENTS.md)와 [모델링 제작 지침](Resource/Documentation/MODELING_PIPELINE_ko.md)을 따른다. 디테일 원본을 먼저 만들고, 가려진 내부 면·중복 정점·불필요한 평면 분할을 정리한다. 삼각형 수를 맞추기 위한 전역 Decimate·임의 비율 축소·무의미한 조각내기는 사용하지 않는다.

- 조립체 GLB와 **기능 단위의 독립 단일 메시 GLB**를 함께 제공한다. 노면 / 도색 / 보도 / 연석 / 난간 / 거더 / 교각 / 배수구 / 발광 표식처럼 실제 교체·정비 가능한 단위로 나눈다. 공통 원점과 포트를 보존한다.
- 독립 파트 최종 상한은 삼각형 변환 후 500개다. 500개를 채우는 것이 목표도, 최소 폴리곤으로 실루엣만 남기는 것이 목표도 아니다. 곡면·모서리·체결부·노면 가장자리 디테일을 유지한다.
- 머터리얼 이름과 역할을 공통화한다: `Road_Asphalt`, `Road_Edge`, `Walk_Paving`, `Marking_White`, `Marking_Center`, `Barrier_Metal`, `Structure_Concrete`, `Signal_Emission`. 공유 메시·머터리얼 인스턴싱이 가능하도록 개별 모듈에 불필요하게 고유 재질을 복제하지 않는다.
- 노면은 반복해도 격자 틈이 보이지 않게 접속 경계를 정확히 맞춘다. 연속 면의 노멀·탄젠트·UV 경계를 점검한다. 램프는 실제 경사 노멀을 사용한다. 길이를 잇는 경계에 중복 상면이나 미세한 틈을 남기지 않는다.
- 차선은 우측통행이다. 중앙선·차로 분리선·가장자리 선만 기본으로 사용하고, 이전에 제거한 지면 직진/좌회전/우회전 화살표를 기본 파트에 다시 굽지 않는다. 노면과 표식을 분리하여 신호 변경과 무관하게 재사용한다.
- SF 개척도시의 압력 패널·내구성 포장·배수·저채도 금속 가장자리·정비 접근부를 사용한다. 장식이 차로 폭·보행 폭·시야를 잠식하지 않게 한다.
- 차량 신호는 지지대 없이 공중에 뜬다. 보행 신호는 횡단보도 양 가장자리의 지면 홀로그램이다. 보행 신호 기둥·별도 신호 헤드는 만들지 않는다. 신호 제어 로직을 메시 내부 색상에 고정하지 않는다.

## 6. 납품물과 통합 절차

1. 소유 컬렉션을 분리한 편집 가능 원본 `.blend`, 독립 Parts GLB, 조립체 GLB, 모듈별 미터 단위 치수·포트 JSON을 제공한다. 기존 다른 확장 컬렉션·리그·애니메이션·기본 장면은 보존한다.
2. JSON에는 bounds, 차선 수, 바닥/노면/상부 높이, 보행 포트, 차량 포트, 도로 외곽, collision envelope, overhead clearance, companion 목록을 포함한다. 표식/신호의 충돌은 생성하지 않는다.
3. 검증 자료에는 원본/최적화 삼각형 수, 파트별 상한, 실제 GLB 재가져오기, 단위·축·포트·높이·노멀·퇴화 면 검사 결과를 남긴다. 접속 오차는 위치 1mm, 접선 0.1도 이내를 목표로 검사하며 예외는 수치와 이유를 명시한다.
4. 미리보기는 2/4차선 직선 접속, T4+4+2, 생활도로 사거리, 폭 전환, 좌우 곡선, 횡단보도-보도 경사로, 램프-고가-램프, 지상 도로와 고가 교차를 포함한다. 실제 게임 쿼터뷰에 가까운 카메라와 옆면 치수도 함께 제공한다.
5. 모델링 작업은 **게임 코드와 `Resource/Runtime` 캐시를 수정하지 않는다.** 원본/납품 검사가 끝난 뒤 게임 에이전트가 캐시 변환·새 모델 등록·절차적 임시 메시 교체를 진행한다. 기존 추가 메시도 용도·축·크기·접속 규격이 맞을 때 재사용한다.
6. 최종 통합 시 건물/프롭이 도로·보도·램프·교각 예약 공간에 들어가지 않는지, 차량과 보행이 같은 포트를 쓰는지, 교차로당 차선 합 제한, 높이가 다른 경로의 독립성, 바이크의 고가 진출입, 교량 상부와 하부의 가림·컬링을 검사한다.

이 요청서는 현재 도시 계획을 최종 아트로 옮기기 위한 문서다. 아트 제작 완료·게임 적용 완료·대상 장비 성능 보장을 의미하지 않는다.
