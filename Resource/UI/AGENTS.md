# UI 리소스 제작 기준

이 폴더는 게임 UI에 사용할 리소스의 제작·보관 공간이다. 아래는 사용자가 지정한 기본 규칙이며 이후 UI 작업에도 적용한다.

## 우선순위와 컨셉

- 가시성과 시인성, 정보 이해와 조작 편의성을 최우선으로 하고 심미성은 그다음에 둔다. 플레이어가 필요한 정보를 빠르게 찾을 수 있어야 하며 화면을 난잡하게 만들지 않는다.
- 게임 컨셉의 기준은 `../../GAME_DOCUMENTATION.md`, 기존 리소스의 아트 방향은 `../AGENTS.md`를 확인한다.
- 현재 컨셉은 에르마의 SF 개척지를 배경으로 하는 쿼터뷰 2.5D 오픈 월드 RPG다. 경이로운 탐험에서 불안과 코스믹 호러로 이어지는 분위기에 맞춘다. 개척지 장비·단말·절제된 홀로그램을 참고하되, 장식·발광·왜곡이 정보 판독을 방해하지 않게 한다.

## 1. 옵션에서 조절할 수 있는 투명도

- UI는 게임 옵션에서 투명도를 조절할 수 있도록 제작한다. 리소스에 고정된 배경 불투명도를 합쳐 조절을 막지 않는다.
- 배경 패널·테두리·아이콘·텍스트는 필요에 따라 별도로 합성하고 불투명도를 제어할 수 있게 구성한다. 투명 배경이 필요한 이미지에는 알파 채널을 보존한다.
- 배경/내용의 조절 범위와 기본값은 실제 UI 제작·게임 통합 시 명시한다. 이 문서 작성만으로 게임 옵션이 구현된 것은 아니다.
- 실제로 지원할 투명도 범위에서 밝은 야외, 어두운 광산, 복잡한 도시 배경에 겹쳐 판독성을 검사한다.

## 2. 텍스트 깨짐과 정렬 검사

- 필수 문구를 `...` 또는 `…`로 대체하거나 줄 수 제한 뒤에서 버리지 않는다. 실제 글꼴 폭으로 줄바꿈하고, 영역을 늘리거나 전체 내용을 보존한 페이지로 나눈다. 페이지 위치와 다음 내용을 읽는 방법을 표시한다. 이야기 원문에 있는 말줄임표는 문장부호이므로 그대로 보존한다.
- 텍스트를 사용하는 UI는 한글·영문·숫자·문장부호의 글리프 누락, 깨짐, 잘림, 겹침을 검사한다. 긴 문구, 여러 줄, 큰 수치와 상태 변경도 확인한다.
- 실제 사용할 글꼴과 표시 크기로 줄바꿈, 기준선, 좌우/중앙 정렬, 행간, 내부 여백을 검사한다. 지원 해상도와 UI 배율에서 실제 렌더 결과를 확인한다.
- 변경 가능한 문구는 가능한 한 이미지에 굽지 않고 게임에서 그리는 텍스트로 분리한다. 이미지에 포함해야 하는 고정 문구도 최종 크기로 확대·축소하여 검사한다.
- 자동 생성 이미지에 포함된 글자를 검증 없이 사용하지 않는다. 원문과 화면을 직접 대조한다.
- 확인한 해상도·배율·문구·문제 수정 결과를 제작물의 검토 기록에 남긴다. 게임에서 확인하지 않은 경우 그 한계를 명시한다.

## 3. 정보 구조와 배치

- 체력·탄약·재장전·스캐너 충전·수배 열도·주행 속도 등 상시/전투 정보는 별도 카드나 창을 만들지 않고 HUD의 게이지·아이콘·핵심 수치로 구성한다. 정상 상태의 장문 설명은 숨기고 필요할 때만 짧게 표시한다. HUD 처리 항목의 배치·조건·게임 데이터·합성 방법은 별도 구현 명세에 기록한다.
- 시각적 위계로 핵심 상태·즉시 행동·보조 정보를 구분한다. 가까이 놓기·유사한 모양·공통 영역으로 관련 정보를 묶는 게슈탈트 원칙을 참고한다.
- 일관된 정렬선, 간격, 여백, 아이콘과 상태 표현을 사용한다. 자주 사용하는 조작은 충분한 크기와 간격을 확보하고, 동시에 제시하는 선택지는 목적에 맞게 묶는다.
- 텍스트와 배경의 명도 대비를 확보하고, 의미를 색상 하나에만 의존하지 않는다. 선택·비활성·경고 등의 상태는 형태·기호·문구를 함께 사용한다.
- 중앙의 플레이어·조준·전투 시야를 보호한다. 상시 정보는 필요한 수준으로 유지하고 상세 정보는 필요할 때 펼친다. 대화·알림·지도 등 동시 표시 상황에서 겹침과 정보 경쟁을 검사한다.
- 구체적인 디자인 이론이나 수치 기준을 채택할 때는 해당 근거와 적용 이유를 제작 문서에 남긴다. 이론을 적용한 결과도 실제 게임 화면의 판독성과 조작 편의로 검토한다.

## 작업 범위

- UI 원본, 출력 리소스와 관련 설명·검토 자료는 `Resource/UI` 아래에 보관한다.
- UI 리소스 제작 요청만으로 게임 코드, 옵션 구현, Runtime 캐시를 함께 변경하지 않는다. 실제 게임 연결은 해당 작업이 요청되었을 때 수행한다.
