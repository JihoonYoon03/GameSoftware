# 디테일 우선 모델링과 보존 최적화

> 2026-10-26 갱신: 현재 납품본은 [크기별 최대 200삼각형·분할 금지 규칙](POLYGON_BUDGET_ko.md)을 적용했습니다. 아래 500 상한·이전 최대값·무손실 수치는 상세 제작 당시의 기록이며, 현재 수치는 예산 목록을 따릅니다.


## 2026-10-22 상세 제작 기록 (현재 납품 상한 적용 전)

2026-10-22 · `detail_first_lossless_cleanup_v1`

폴리곤 예산은 디테일을 포기하기 위한 기준이 아닙니다. 필요한 실루엣·표면 구조·작동부를 먼저 만든 뒤 불필요한 면만 정리합니다. 납품 파트는 기존 팩처럼 **삼각형 변환 후 500개 이하**이며, 원본에는 이 상한을 강제하지 않습니다. 단순한 평면 부품에 불필요한 면을 채우지도 않습니다.

## 현재 반영 범위

비행체 4종의 기본/교체 조합과 도시·도로·야외 프롭 34종에 이어 지상 이동수단 5종, 선별한 기존 창호·가구·횡단보도, 새 건물 5종의 모듈까지 적용했습니다. 이어서 인체 관련 기존 785개 파트를 모두 교체하고 착용 외장 69개를 추가했습니다. 도로계획 확장 428개를 포함해 현재 서로 다른 1,676개 파트의 상세 원본과 최적화본이 있습니다. 몹·통행로 전체를 다시 모델링한 상태는 아닙니다. 다른 도구가 만든 자산과 현재 Blender 기본 진입 장면은 보존합니다.

코일 외장에 체결부·점검 슬롯을 추가하고 아크 곡면을 세분화했습니다. 비행체 선체의 점검판·흡기구, 캐노피 프레임, 좌석 이음선·계기판, 엔진 통풍구와 해치 잠금부를 보강했습니다. 프롭에는 제조 모서리, 전력 장비 점검판, 화물실 패널·실링, 광자 수집판 그리드, 조명·스캐너의 기능 디테일을 반영했습니다. 도로 노면과 접합 좌표는 유지합니다.

차량 신호기는 좌우 안정화 장치를 각각 정비할 수 있는 실제 파트로 나눴습니다. 하우징·좌우 안정화 장치·정지/대기/진행 표시의 **6개 파트**입니다. 보행자 안내는 계속 바닥 홀로그램을 사용합니다.

## 실제 제작 단계

1. **상세 원본:** 형상과 기능 디테일을 제작합니다. 기계 외장의 모서리와 곡선 프로파일을 충분히 표현하고 원본 메시를 따로 남깁니다.
2. **내부 면 정리:** 하나의 파트 안에서 같은 본에 고정된 다른 닫힌 볼륨 속에 완전히 들어간 면만 제거합니다. 볼록한 외장 안에 면 전체가 엄격히 포함되는지 검사합니다. 부분적으로 걸친 면, 다른 가동 본에 속한 부위, 오목한 대상에는 이 삭제를 적용하지 않습니다.
3. **중복·평면 정리:** 같은 본의 중복 정점과 퇴화 면, 필요 없는 평면 분할을 정리합니다. 재질·관절 경계를 보존하고 작성된 바깥 방향의 면 순서를 유지합니다.
4. **원본 비교:** 삭제가 허용된 내부 면을 제외한 원본 표면과 최적화 표면을 양방향으로 비교합니다. 정점과 삼각형 내부 표본에서 거리를 검사하며, 0.05mm 이상 달라지면 평면 정리를 되돌려 상세 토폴로지를 유지합니다. 무조건적인 비율 Decimate를 하지 않습니다.
5. **납품 검증:** 최종 파트의 500삼각형 상한, UV·법선·재질·가중치·본·조립을 검사하고 GLB로 저장합니다. 초과한 파트가 있으면 내보내기 전에 중단하여 기능 단위 재설계 또는 수동 정리를 요구합니다.

재질별 하드 에지와 UV는 최적화 후의 실제 형상에 맞춰 유지합니다. 여러 정비 부품을 파트로 나누는 것은 허용하지만 숫자만 맞추려고 삼각형 묶음으로 잘라 내는 방식은 사용하지 않습니다.

## 결과를 보는 위치

- `Source/Erma_Resource_Library.blend` → `17_Detail_Sources`: `Detail__파트명`으로 보관한 편집 가능한 원본. 각 원본에는 대응 납품 파트 이름과 원래 리그·본 가중치 정보가 있습니다. 파트는 공통 바인드 좌표에 겹쳐 있으므로 하나씩 표시합니다.
- 같은 파일의 `00_Library` → `10_Air_City_Expansion`: 실제 내보낸 최적화 파트.
- `18_Detail_Comparison`: 이전 단순 모델 → 상세 원본 → 보존 최적화본을 동일한 크기로 비교합니다. 코일·엔진·전력 장비의 예제가 있습니다.
- `Preview/23_detail_pipeline_comparison.png`: 위 비교 장면의 렌더.
- `Validation/detail_pipeline_report.json`: 부위별 원본/최종 삼각형 수, 지운 내부 면 수, 표면 오차와 상세 토폴로지 유지 여부.
- `Validation/air_city_source_report.json`, `export_report.json`, `air_city_roundtrip_report.json`: 최종 메시·GLB·재가져오기 검사.

기존 확장 219개 납품 파트의 현재 상세 원본 합계는 **27,146삼각형**, 최적화본은 **25,606삼각형**입니다. 디테일을 만든 다음 **1,540삼각형**을 정리했습니다. 최종 파트의 최대값은 **464삼각형**입니다. 각 파트의 감소량은 달라 일부는 원본 수치를 그대로 유지합니다. 이 수치는 목표 감축률이 아니라 이번 형상의 검사 결과입니다.

## 재제작

제작 도구는 `Tools/build_air_city_expansion.py`, `Tools/build_refined_city_assets.py`, `Tools/build_character_detail_expansion.py`, 공통 구현은 `Tools/detail_mesh_pipeline.py`입니다. 후속 제작은 통행로 제작 뒤에 실행합니다. 기존 전체 팩을 초기화하지 않고 해당 확장만 갱신합니다.

```text
blender --background --python Resource/Tools/build_air_city_expansion.py -- --geometry-check
blender --background --python Resource/Tools/build_air_city_expansion.py
python Resource/Tools/verify_resource_pack.py
blender --background --factory-startup --python Resource/Tools/verify_air_city_roundtrip.py
```

첫 명령은 메모리에서 상세 제작·정리·상한을 확인하고 `detail_draft_check.json`을 남깁니다. Blender 원본과 GLB를 갱신하는 것은 두 번째 명령입니다. 제작 도구를 다시 실행하면 해당 확장의 수작업 수정은 덮어쓰므로 별도 파일로 보관하거나 제작 정의에 반영하십시오. 보관한 상세 원본은 자동으로 파일 수정을 감지하는 실시간 작업물이 아닙니다.

최적화 후에도 상한을 넘는 초안이 있으면 원본 장면을 `Source/Drafts/Air_City_Detail_Overbudget.blend`에 보관하고 납품 내보내기를 중단합니다. 따라서 원본 작업을 잃지 않고 기능 단위를 재설계할 수 있습니다.

후속 갱신은 [유리창·건축 안내](REFINED_CITY_ko.md)를 따릅니다. 후속 보고서의 183개 파트는 상세 원본 25,256 → 최적화 23,475삼각형이며 최대 386삼각형입니다. 두 보고서에는 교체된 비행체 프레임 8개가 중복되므로 적용 범위는 합집합 394개입니다. 유리·실링을 실제 교체 모듈로 분리하여 디테일을 보존했습니다.

캐릭터 갱신은 [별도 안내](CHARACTER_DETAIL_ko.md)를 따릅니다. `25_Character_Detail_Sources`에 854개 원본, `26_Character_Detail_Comparison`~`28_Character_Head_Study`에 비교·확대 장면이 있습니다. 181,880 → 174,980삼각형으로 디테일을 보존하며 정리했고, 캐릭터 파트의 최대값은 448삼각형입니다.

도로계획 확장은 [RoadPlan 안내](ROAD_PLAN_ko.md)를 따릅니다. `build_road_plan.py`가 P0/P1 88개 모듈·428개 파트의 상세 원본 43,680 → 최적화 40,571삼각형을 보관하며 최대 492삼각형입니다. 매우 얇은 표식의 표면 검사는 엄밀한 삼각형 집합 동일성과 double 정밀도 거리로 검증하고, 실제 위치 이동을 놓치지 않는 회귀 검사를 유지합니다. UV·법선·탄젠트와 실제 GLB 접속을 별도로 검사합니다.
