## 제작 내용

**115개 조립 모듈 / 독립 메시 497개 / 새 GLB 612개**입니다. 파트당 최대 **288삼각형**으로, 삼각형 변환 후에도 500개 이하입니다. 노면·차선·보도·연석·안내 표식을 별도 파트로 보관했습니다. 정적인 통행로 자산이므로 스켈레톤과 애니메이션은 추가하지 않았습니다.

## 연결 규격

Blender는 **+Z 위**, 직선 진행 축 **+X**입니다. GLB는 **+Y 위**로 내보냈으며 좌표 변환은 `(x,y,z) → (x,z,-y)`입니다. JSON의 위치·방향은 Blender 좌표계입니다. GLB에 사용할 때 접속점과 방향 벡터도 함께 변환하십시오. 게임에서 1월드 단위=2m를 사용한다면 메시와 접속점 위치를 모두 0.5배 합니다.

도로는 차선당 **3m**, 전체 폭은 **6/12/18m**, 노면 높이 **Z=0**입니다. 기존 `Road_2Lane_4m`, `Road_4Lane_4m`, `Road_6Lane_4m`과 동일한 폭·높이를 사용합니다. 보행로 표면과 연석 상단은 **Z=0.15m**, 보행로 폭은 **2/4m**입니다. 경사로는 길이 4m에 걸쳐 0.15m에서 0으로 낮아지며 기울기는 3.75%입니다. 점자색 띠는 끝부분에 붙였습니다.

각 `ports`에는 `id`, `position_m`, `outward`, `width_m`, `kind`가 있습니다.

1. 같은 `kind`와 같은 `width_m`인 접속점을 고릅니다. 높이가 다른 연결은 경사로를 거칩니다.
2. 다음 모듈의 `outward`가 기존 모듈 접속 방향의 반대가 되도록 Z축 회전합니다.
3. 두 `position_m`이 같은 월드 위치에 놓이도록 이동합니다.
4. 크기를 늘려 맞추지 않습니다. 폭이 다르면 전환 모듈을 사용합니다.
5. `walk_companion`이 있으면 도로와 **같은 위치·회전**에 놓습니다. 곡선·교차로·전환부 보도가 자동으로 맞습니다.

기존 모듈의 월드 변환을 A, 연결할 모듈의 회전을 R이라고 할 때 이동량은 `A·port_A.position − R·port_B.position`입니다. 실제 연결 예제에는 도로 접속 8개와 횡단보도·경사로·끝막음 보행 접속 6개가 들어 있습니다.

새 곡선의 원점은 **진입 중심선 끝점 (0,0)**입니다. 진입 진행 방향은 +X이며 좌회전하도록 만들었습니다. 끝점은 `(R·sinθ, R·(1−cosθ))`, 종료 접선은 `(cosθ,sinθ)`입니다. 종료 포트를 먼저 연결하면 우회전으로 사용할 수 있습니다. 거울 반전이나 음수 스케일은 필요 없습니다. 반대 곡선과 조합하면 S자 구간을 만들 수 있습니다.

기존 `Road_Curve90_R9m`은 원점이 원호 중심이므로 새 곡선처럼 배치하지 마십시오. 기존 `City_Sidewalk_2x4m`은 상판 0.16m, 연석 최고 0.26m로 새 보행로와 높이가 다릅니다. 이번 모듈끼리 연결하는 것을 권장하며 기존 보도에 연결할 경우 높이와 연석을 별도로 맞춰야 합니다. 기존 자산은 수정하지 않았습니다.

횡단보도는 길이 4m의 도로 모듈이며, 양쪽 보행 접속점의 폭은 4m·높이는 0m입니다. `Transit_Walk_W4_AccessibleRamp_4m`의 `flush` 포트를 연결하고, 반대쪽 `raised` 포트에 폭 4m 보행로를 연결하면 단차 없이 건널 수 있습니다. 보행로는 차량 차선과 독립적으로 배치할 수 있습니다.

## 하늘의 비행 안내

하늘을 채우는 면·터널·문틀 대신 **폭 약 3.5cm, 길이 65cm인 짧은 양측 표식**을 약 8m 간격으로 둡니다. 방향 표식도 양측에만 있으며 중앙 **5m 폭은 완전히 비어 있습니다**. 알파 투명도 없이 실제 메시 자체를 줄였으므로 투명 정렬이나 불투명 렌더러에서도 넓은 판으로 보이지 않습니다. 발광 세기는 0.25입니다.

직선·곡선의 통행 폭은 6m, 곡선 중심선 반경은 32/64m입니다. 비행체의 실제 충돌 폭과는 독립적인 안내 규격이므로 통행 경로·고도·교통 제어는 개발에서 결정합니다. 파트는 로컬 Z=0 부근에 있고, 조립체 전체를 원하는 비행 고도로 올립니다. 교차로 중앙에는 표식도 두지 않았습니다. 비행 표식에는 충돌을 생성하지 마십시오.

표식은 기존 길 위에 겹쳐 켜는 장식이 아니라 기존의 굵은 비행 경로 표시를 대신할 자산입니다. 실제 게임의 기존 비행 경로 표시 교체와 거리별 표시·숨김은 별도 개발 작업입니다. 이번 작업에서는 `Runtime` 캐시와 게임 코드를 수정하지 않았습니다.

## 검증

- `transit_source_report.json`: 원본 파트 수·삼각형·UV·퇴화 면·유효 좌표.
- `export_report.json`: 기존 자산을 포함한 전체 GLB의 실제 메시·법선·UV·리그·클립.
- `transit_connection_report.json`: 새 모듈 전체의 실제 접속면, 도로/보행로 곡선 경계 일치, 조립 예제의 위치·높이·접선, 비행 표식의 중앙 빈 영역과 평면 면적.
- `transit_roundtrip_report.json`: 저장된 Blender 원본을 다시 열고 대표 GLB 18개를 재가져와 메시 수·단위·방향·실제 외곽·UV·삼각형 수 확인.

검증 결과 파일은 `Validation/`에 있습니다. 게임 화면에서 최종적으로 보이는 선 두께와 밝기는 게임 카메라·재질·표시 거리에 따라서도 달라집니다.

재생성 도구는 `Tools/build_transit_kit.py`입니다. 기존 자산을 유지하고 이 확장 태그에 속한 파트·도감만 갱신합니다. 같은 파트를 수작업으로 수정했다면 별도 사본으로 보관한 뒤 실행하십시오.

횡단보도 페인트는 `Transit_CrosswalkPaint_2L/4L/6L` 파일로 별도 제공됩니다. 이 파일에는 보행로와 노면이 없습니다. 연결 예제의 횡단보도 양측 직선 보행로는 8m에서 2m로 줄였으며 경사로·끝막음은 별개입니다. [분리 규칙과 비교 장면](REFINED_CITY_ko.md)을 참고하십시오.
