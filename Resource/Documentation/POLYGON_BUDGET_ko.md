## 2026-11-23 개정 — v4 렌더링 최적화(R1~R4) 전제 규모별 폴리곤 상한

2026-11-23 확정된 차세대 렌더링 최적화 계획([RENDER_RESOURCE_REQUEST.md](../RENDER_RESOURCE_REQUEST.md) 7절 · `GAME_DOCUMENTATION.md` 53절)에 따라, **인덱스 버퍼(EBO)·정점 압축(R1) + 다단계 LOD0~2·전용 그림자 프록시(R2) + 계층/Hi-Z 오클루전 컬링·MDI(R3) + 공유 PBR 텍스처 배열(R4)**을 적용하는 **신규 및 CQ-11 리메이크 자산의 폴리곤 상한**을 아래와 같이 상향 개정한다.

- **핵심 원칙 유지:** 디테일 우선 제작 → 불필요한 내부 면·평면 정리 → 규모별 상한 준수. **한도를 맞추기 위한 임의 파트 분할·GLB 파일 증가 금지.** 볼트·나사·미세 홈·패널선·봉제선은 메시가 아닌 공유 Normal/ORM/Trim 텍스처로 표현한다.
- **적용 게이트:** R1~R4(v4 팩·EBO·36 B 압축 정점, 4단계 LOD0~2·그림자 프록시, Mega-VBO/EBO MDI, 불변 PBR 텍스처 배열·`skinSlot` 공유·72본 Mixamo 리그 지원)가 2026-11-24 엔진 통합·검증을 완료했다. 기존 `v3` 유지 파트는 억지 재분할 없이 보존하고, 신규/CQ-11 v4 자산에는 아래 파트·조립체 예산을 적용한다. 중형 이상은 LOD0·LOD1·LOD2와 그림자 프록시를 함께 납품하며, 유형별 생략·컬링·LOD2 겸용 조건은 아래 표와 그림자 프록시 기준을 따른다.
- **모듈러 3계층 캐릭터 예외·합산 규칙 (2026-11-24 추가):** 신규 인간형 모델은 **Mixamo 스켈레톤 프리셋**을 기본 골격으로 하며, 캐릭터의 **1계층(단일 마스터 인체 바디) + 2계층(의복 1~2메시) + 3계층(헤어·강체 소켓 파츠)**은 디테일·노멀·웨이트 보존을 위해 소형 파츠 800삼각형으로 억지 절단하지 않는다. 대신 **캐릭터 1명 3계층 합산 예산(일반 NPC 권장 2,000~4,000 / 최대 12,000, 플레이어·주연 권장 3,500~8,000 / 최대 18,000)** 안에서 연속 메시로 제작하며, 세부 규격은 [RENDER_RESOURCE_REQUEST.md](../RENDER_RESOURCE_REQUEST.md) 7.3절을 따른다.

## 기존 v3 납품본 기준 — 2026-10-27 (최적화 이전 2,293파트 유지분)

**기존 v3 납품 파트당 최대 200삼각형. 한도를 맞추기 위한 파트 분할·추가 GLB 생성은 금지합니다.** 기존 파트 하나의 모든 재질 구간을 합산합니다. 사각형은 내보내기 때 삼각형 2개로 계산합니다.

현재 **2,293파트 / GLB 2,575개**이며, 이번 변경으로 추가된 모델 파일은 **0개**입니다. 파트 ID·경로·조립 파트 수·장면 노드 수를 유지했습니다. 실제 최대값은 **196삼각형**, 전체 고유 파트 합계는 **311,692 → 247,796삼각형**입니다. 한도보다 적은 파트에 면을 채우지 않습니다.

## 크기에 따른 상한

최적화 전의 공통 바인드 좌표에서 각 파트 경계 상자의 대각선 길이 D를 측정했습니다. 실제 단일 파트 중 가장 큰 `Transit_AirGuide_Curve90_R64_EdgeTicks-1`의 **89.392709m**를 고정 기준 R로 사용합니다. 가장 큰 파트도 실제로는 156삼각형이며 200개를 채우지 않습니다.

프로젝트 상한은 `4 × floor((176 + 24 × log(1 + D/0.005) / log(1 + R/0.005)) / 4)`를 176~200 범위로 제한합니다. 외곽 곡면을 지킬 수 있도록 크기별 예산을 200 이내에서 재배분했습니다. 작은 부품의 상한은 낮추면서 얼굴·손의 디테일이 큰 통행로 때문에 사라지지 않도록 로그 배분을 사용했습니다. 현재 적용 상한은 **184, 188, 192, 196, 200삼각형**이며 각 파트의 정확한 수치는 [예산 목록](part_polygon_budgets.json)에 있습니다. 이 공식은 이번 프로젝트의 제작 기준입니다.

로우 폴리 전체에 통용되는 ‘파트당 300폴리곤’ 표준은 확인되지 않았습니다. [Khronos 실시간 자산 제작 지침](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md)은 필요한 형상에 폴리곤을 배분하고 작은 디테일은 표면 정보로 표현하는 원칙을 다룹니다. [Unity LOD 안내](https://unity.com/glossary/level-of-detail)도 거리·화면 크기에 따른 디테일 조절을 설명합니다. 따라서 다른 숫자를 업계 표준으로 대체하지 않고 사용자의 200 상한을 적용했습니다.

## 디테일과 파일 수를 지키는 제작 순서

1. 필요한 실루엣·작동부·유리 패널·관절·패널 경계 등 디테일을 먼저 제작하고 편집 원본을 보관합니다.
2. 중복·불필요한 평면 분할·항상 가려진 내부 면부터 정리합니다.
3. 같은 파트 안에서 면 배치를 다시 정리합니다. 재질 경계, 스킨 가중치 영역, 접속점과 보행 폭을 보호합니다. 임의 비율의 일괄 감축을 기본으로 사용하지 않습니다.
4. 그래도 초과하면 나사·봉제선·작은 홈·트림 등의 부가 요소를 먼저 통째로 제거합니다. 외곽 곡선을 먼저 거칠게 만들지 않으며, 특히 추진장치의 원래 곡선 분할을 보존합니다. 한도 충족 때문에 기존 파트를 잘라 새 파트·파일을 만들지 않습니다.
5. 실제 GLB를 검사하고 비교 렌더와 움직이는 스킨을 확인합니다. 이번 단계는 디테일 손실을 일부 허용하므로 과거의 ‘외부 표면 무손실’ 판정을 현재 결과에 그대로 적용하지 않습니다.

부상 필드 16파트는 세 갈래 외장과 중심 코어의 원래 곡선 면을 그대로 복원했습니다. 각 188삼각형이며 실제 GLB의 삼각형 집합을 원본과 대조합니다. 작은 볼트·홈을 제거하고 발광은 기존 내벽의 재질로 표현해 별도 띠 형상에 쓰이던 면을 줄였습니다. 캐릭터·의복도 나사와 봉제선부터 제거하고 주 형상의 앞/옆 윤곽을 보호합니다. 차량 유리는 패널과 실링의 윤곽을 유지합니다. 평평한 페인트·홀로그램은 불필요한 솔리드 뒷면을 줄였습니다.

도로의 노면 접속 위치·끝단 접선·보행 유효 폭·경사·원래 충돌 영역은 유지합니다. 땅에 묻힌 면을 지워 달라진 시각 경계는 `render_bounds`에 따로 기록하며, `collision_envelope`를 시각 메시 크기에 맞춰 줄이지 않습니다.

## 원본과 납품본
