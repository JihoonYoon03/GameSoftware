튜토리얼 이동 구간과 격리 구역 콘텐츠 확장

모델은 차량(Coupe, Shuttle, Hauler, Patrol, JetBike), 캐릭터(Explorer, Engineer,
Guard, Medic, Researcher), 건물(Habitat, Terraced, Workshop, Dome, Observatory)
각 5종이다. 타입과 body/accent/emission 팔레트를 분리하여 같은 형상도 다른 색을 가진다.
파일 모델 캐시는 버전 3으로 전환한다.
약 238KiB 라이브러리는 힙에 보관하고 모든 모델을 해당 저장 공간에 직접 생성하여
디버그 빌드의 큰 지역 변수·값 반환 임시 객체에 의한 스택 초과 경로를 제거했다.
차량 로컬 +X가 전방이며 헤드라이트는 앞, 노즐은 뒤, 불꽃은 -X로 나온다.
방향 전환 시 차체와 이펙트를 함께 반전한다.

진행: 집 단말 -> 리아 -> 전망대 진입 -> 관문 신호 조사 -> 하강 -> 바이크 E 탑승
-> 제트 주행 회랑 -> 격리 구역.
주행 조작: W/S 측면 조종, D 가속, A 감속, Space 부스트. 거리 1800.
시차 스크롤 배경, 장애물 회피, 접촉 감속을 사용한다. 도착하면 도보 전투로 전환한다.

격리 구역은 64x64, NPC 20명, 적 정원 72기, 팀 작업장 4개이다.
기술자 수리, 경비 방어와 실제 몹 처치, 운송 인력 보급, 의무 인력 치료,
관측 인력 수리 지원을 수행한다. 설비는 보급 대기/수리/위협/가동 상태를 가지며
가동 유지 후 정비를 반복한다. 체력이 소진된 NPC는 안전 구역에서 회복한다.
NPC 처치 수와 플레이어 경험치/처치 수를 분리한다.

모니터: http://127.0.0.1:17707/
모델 형태/색상 카탈로그: http://127.0.0.1:17707/models.html
카탈로그는 실제 캐시 형상의 형태/팔레트 확인용이며 게임의 최종 재질/그림자/
후처리/불꽃 합성은 게임에서 확인한다. 정적 소스/구문 확인만 수행하며 빌드와 실행
결과 확인은 사용자가 수행한다.

사용자 확인: 차량 전후 부품과 불꽃 -> 각 타입/색 -> 전망대 입장/조사/하강
-> 바이크 조종/시차 스크롤/도착 -> 팀 보급/수리/방어/치료 -> 모니터 상태 일치
-> FPS/드로우 콜/NPC 갱신과 길 찾기 비용 확인.

상세 구현 내용과 확인 순서는 CONTENT_EXPANSION.md, JSON 필드는 Game_Monitoring.md 참고.

형상 수치 검토: 폴리곤/유리 면 214개에서 오목한 면과 면적 0인 면 없음.
헤드라이트 중심 10개 및 선 끝점 20개가 차체 면 내부/경계에 있으며,
추진기 앵커 10개는 노즐 면에 있다. 최대 파츠 68개(용량 96개).
실제 렌더링 결과 확인은 별도로 수행한다.

협업 프로파일링: npc_cooperation, npc_shots, npc_enemy_kills,
workstation_repair_completions, workstation_supply_deliveries, npc_rescues.

기존 버전 3 캐시 형식은 유지한다.
수정 적용과 소스 확인은 완료했지만 재빌드·재실행에서 오류 해소 여부는 확인 대기다.
예외 주소만으로 호출 경로를 확정하지 않았으며, 재발 시 디버거 호출 스택을 확인한다.
