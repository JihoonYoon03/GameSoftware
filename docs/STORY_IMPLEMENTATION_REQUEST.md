# 《침묵하는 관문》 대사 진행·후속 스토리 구현 요청서

작성: 2026-10-23  
기준 원고: [게임 개발 통합 문서 4절 개정 원고](../GAME_DOCUMENTATION.md#story-revision)

이 문서는 **이후 개발을 위한 요청 사항**이다. 현재 코드에서 수정한 문구와 앞으로 만들어야 할 기능을 구분한다. 스토리와 완성 대사는 통합 문서를 기준으로 하며 여기에는 진행 조건·연출·상태·검증 기준을 적는다. 2장 이후 맵이나 대화 시스템이 이미 구현되었다는 뜻이 아니다.

## 1. 확인한 개발 상태와 이번 반영 범위

게임은 Windows C++17·OpenGL 기반 쿼터뷰 SF 탐험 RPG다. 에르마의 개척 생활과 동료 관계가 관문망의 이상, 우주적 공포와 상실로 이어진다. 현재 실제 플레이 구간은 도시 도입부, 무작위 광산 프롤로그, 1장 현장 세 곳과 헤일로 기록 대조까지다. 연결 도시 5곳·주민·교통·도시 전투·악명·의료 이송은 존재하지만 도시별 메인 스토리 장이 따로 구현된 것은 아니다.

| 구분 | 현재 상태 |
|---|---|
| 이번 코드 반영 | 도시·광산·1장 대사와 목표·기록 개정, 단계별 리아 대사, 재조사·보고 후 대화 조건, 주민 일상 대화, 거래·출구·미구현 지역 안내 |
| 원고만 작성 | S20~S25(2장), S30~S36(3장), S40~S44(4장), S50~S52(에필로그) |
| 아직 필요한 시스템 | 순차 대화·화자 표시·선택지·대사 이력, 대화 완료와 퀘스트 상태의 연결, 영구 저장·복원, 후속 지역·사건 |
| 기존 제한 | `ShowNotice()`는 문자열 하나를 12초간 표시한다. 새 알림이 덮어쓰며 패널은 최대 3줄이다. 1장 대조는 3초·8초의 경과 시간으로 진행한다. 긴 대본을 그대로 넣으면 누락·덮어쓰기·진행 불일치가 생긴다. |

이번 작업은 사용 중인 게임 실행 파일을 교체하지 않는다. 기존 이동·충돌·지도·모델 제작 작업과 독립된 서사 요청서다. 빌드·실제 화면·연속 플레이는 저장소 협업 규칙에 따라 사용자가 확인한다.

## 2. 우선 구현: 대사가 읽히는 진행 구조

### R01. 알림과 대화를 분리한다

수정 시작점은 `SimpleGame/Game.cpp`의 `ShowNotice()`, `Game.h`의 `GameState`, `SimpleGame/Hud.cpp`의 `Hud::DrawNoticePanel()`이다. 현재 파일 구조를 확인하고 기존 입력·HUD 책임을 유지한다. 새 소스 파일을 만들면 프로젝트와 필터에도 등록한다.

- 전투·획득·재장전·거래 결과는 짧은 알림으로 유지한다.
- 스토리는 장면 ID·대사 ID·화자·전달 방식(현장/무전/단말/수신 기록)·본문을 갖는 순차 대화로 처리한다. 표시 이름과 영구 ID를 분리한다.
- 한 페이지에 한 화자, 1~2문장을 표시한다. 시스템 조작 설명과 보상은 대사 본문에 섞지 않는다. 행동·카메라 지문은 연출 이벤트로 실행한다.
- 다음 페이지는 `E` 또는 `Enter`, 이전 대사 확인은 이력 화면에서 제공한다. 다음 페이지로 넘긴 입력이 월드 상호작용까지 실행되지 않게 소비한다. E를 길게 눌러 페이지 전체를 건너뛰지 않게 한다.
- 자동 종료를 기본으로 두지 않는다. 읽기 속도나 실제 대기 시간으로 스토리 성공 여부를 판정하지 않는다.
- 글자 수가 아니라 실제 글꼴 폭으로 줄바꿈하고 UTF-8 문자 경계를 지킨다. 최대 줄을 넘으면 다음 페이지로 나눈다. 화자명·선택지·조작 범례도 화면 밖으로 잘리지 않게 한다.
- 대화 도중 전투 알림은 중요 대사를 덮어쓰지 않는다. 별도 위치나 대기열을 사용한다. 무한히 쌓이지 않게 유사 전투 알림은 합친다.

완료 기준: 전망대 수신 음성, 플레이어 관찰, 리아의 반응을 서로 다른 페이지·화자로 읽을 수 있다. 긴 카인 고백과 선택지가 누락 없이 표시되며 다음 입력으로 뒤의 월드 상호작용이 같이 실행되지 않는다.

### R02. 완료 시점을 사건에 연결한다

현재 `MineQuest::Advance()`와 1장 행동은 E를 누른 시점에 상태를 바꾼다. 모든 행동을 일괄적으로 대화 종료까지 미루지 말고 다음처럼 나눈다.

| 행동 | 즉시 확정 | 대화 종료 후 확정 |
|---|---|---|
| 배전반 조작 | 전력·격벽·이동 가능 상태 | 발견 반응 대화의 읽음 기록 |
| 아이템·장부 회수 | 보유품·조사 사실, 1회 지급 표식 | 설명 대사의 읽음 기록 |
| 카인 고백·선택 | 장면 시작·현재 페이지 임시 보존 | 공개 완료·선택 값·다음 대화 분기 |
| 기록 대조 결론 | 대조 자료 확보 상태 | 결론 대화 완료·장 완료·다음 출발 항목 |
| 위기 구간 출발 | 확인 창 표시만 | `출발한다`를 확정했을 때만 지역 단계 변경 |
| 생존자 구조 | 실제 안전 지점 도착·인수 확인 | 후속 감사 대화의 읽음 기록 |

장면 상태에는 최소한 `not_started`, `in_progress`, `completed`를 구분한다. 페이지 위치, 선택 확정 여부, 이미 실행한 이벤트/보상 ID를 보존한다. 같은 장면의 재시작·재접속으로 보상·물자 차감·장 완료를 중복 실행하지 않는다. 화면을 그리는 함수가 플래그를 수정해서는 안 된다.

1장 `ChapterOneLevel::Update()`의 3초·8초 결론 진행을 대사 종료 이벤트로 교체한다. 조명 점등 시간은 연출에만 사용한다. 대화를 천천히 읽어도 마지막 기록과 결론이 사라지지 않아야 한다.

### R03. 일시정지·위험·의료 이송에 대응한다

- 안전한 대화 장면에서는 이동·사격·근접·승하차를 잠그고 이미 누른 공격 입력을 해제한다. 선택지 키와 게임 조작 키가 충돌하지 않게 한다.
- 생존과 전투가 계속되는 무전은 비차단 방식으로 표시하되 중요한 문장은 이력에 남긴다. 필수 선택은 안전 지점에서만 받는다.
- 적이 남은 현장에서 무조건 대화 일시정지를 열어 회복·무적 수단이 되지 않게 한다. 교전 중에는 우선 짧은 무전만 제공하고 안전해진 뒤 정식 대화를 연다.
- 의료 이송 중 대화·맵 입력을 잠근다. 복귀 후에는 이송 안내를 보여 주고 중단한 대화를 안전 지점에서 재개할 수 있게 한다. 회수한 장부나 인수 완료한 생존자를 원상복구하지 않는다.
- 메인 NPC가 중상일 때는 현행 60초 복귀 규칙을 유지한다. 대화 표식은 중상 상태에서 숨기며 의료 지원 중임을 안내한다.
- 일시정지·지도·창 포커스 상실 때 대화의 표시 시간과 연출 시간이 따로 흘러 결론을 건너뛰지 않게 한다.

### R04. 재방문과 조사를 기록한다

`MineQuest::GetRiaDialogue()`는 현재 목표를 구어체로 알려 주는 진입점이다. 후속 대화 데이터로 옮겨도 다음 단계 대응을 보존한다.

| 상태 | 다시 대화했을 때 알려 줄 내용 |
|---|---|
| `ShowRecord` | 전망대 기록을 보여 달라고 요청 |
| `CheckCityRelay` | 광장 수신망에서 경로 대조 |
| `TravelToMine` | 바이크 이동, 입구 하차·입장 |
| `BypassPower` | 주 갱도 끝 배전반과 격벽 전력 |
| `InvestigateSignal` | 열린 격벽 너머 신호 |
| `InvestigateGlyph` | 신호 옆 벽면 문양 |
| `CollectCoordinates` | 안쪽 단말 좌표 |
| `ReturnToHalo` | 입구 → 직접 운전 → 헤일로 수신망 보고 |
| `Complete` | 보고 완료, 1장 현장 출발 |
| 1장 세 현장 완료·미대조 | 헤일로에서 세 기록 대조 |
| 1장 대조 완료 | 수로 기록과 후속 조사, 현재 재방문 가능한 활동 |

`J 조사 기록`을 프롤로그부터 제공해 인물 이름·관문 N-0·설비 N-0/17·확보 사실·다음 행동을 다시 확인할 수 있게 한다. N-0은 관문, N-0/17은 외곽 설비 번호다. 조사 전 사실과 가설을 미리 기재하지 않는다.

광산은 재입장마다 지형·적·구조 대상이 새로 생긴다. 프롤로그 조사 플래그와 현장 회차의 구조 기록을 구분하고, 반복 구조 NPC를 서사상 매번 똑같이 실종되는 인물로 취급하지 않는다. 후속 메인 장면의 고정 탐사대원은 이 무작위 풀과 분리한다.

## 3. 장면별 제작과 연결 요청

아래의 원고 ID는 통합 문서의 대본과 일치해야 한다. 기존 `MQ00_SIGNAL_FALLEN`, `MQ01A`~`MQ01D`, `MQ02A`~`MQ03D` 명칭을 유지한다. 신규 ID는 이번 요청의 제안이며 코드에 이미 존재하지 않는다.

| 장면 / 퀘스트 | 진입 조건 | 필수 상호작용·연출 | 완료와 다음 행동 |
|---|---|---|---|
| 도입·`MQ00_SIGNAL_FALLEN` | 새 게임 | 단말 메시지, 리아 동행 안내, 전망대 수신 기록, 하강 후 대조 | 실제 현행 광산 진행 순서 유지 |
| 1장 추가 일상 대화 | 각 현장 완료 | 조명 수리 후 짧은 휴식, 구조 후 카인의 인원 재확인, 전력 복구 후 마라 반응 | 선택 대화의 읽음만 기록. 메인 수집 과제 추가 금지 |
| S20 / `MQ02A_RETURN_ROUTE` | `recordsCompared && waterwayUnlocked` | 수로의 실제 진입점, 시작 귀환 표식, 두 조사 지점 안내 | 측량소·야영지 자유 순서 조사 |
| S21 / `MQ02A` | 수로 입장 | 정지 장비와 최근 점검 기록을 별개로 조사 | `survey_station_investigated` |
| S22 / `MQ02B_KAIN_RETREAT` | 야영지 점호 기록 | 고백, 3개 선택지, 공통 종료 대사 | 야영지 조사·과거 공개·선택 확정 |
| S23 / `MQ02C_VEIL_RELAY` | 측량소·야영지·고백 완료 | 도식·가동 오차·승인 원본과 삭제본 비교 | 장막 가설·관측국 문서 확보 |
| S24~25 / 신규 `MQ02D_REPORT_PREPARE` | 두 증거 확보 후 귀환 | 보고·날짜 불일치·자유 준비·출발 확인 | 2장 완료 후, 출발 확정 때 3장 진입 |
| S30 / `MQ03A_FORCED_ACTIVATION` | 3장 출발 확정 | 도시 선로·기동기 차단, 독립 전원, 되돌아오는 중단 요청 | 도시 대피 전환 |
| S31~33 / `MQ03B_HALO_EVACUATION` | 위기 지역 진입 | 집결로·부상자·통신, 측면 구조, 전원 우선순위 | 필수 대피 완료 |

| S50~51 / 신규 `MQE01_EMPTY_CHANNEL` | 4장 완료 | 대피소·의료소·정비소 확인, 이전 선택의 후속 대화 | 자유 복구 활동·기록 정리 항목 |
| S52 / 신규 `MQE02_NEREUS_SIGNAL` | 복구 필수 대화 후 기록 정리 선택 | 17일 후 날짜 전환, 네레우스 식별자와 미확인 송신 시각 | 다음 편 조사 목표·자유 플레이 복귀 |

### 지역 제작에서 지켜야 할 연결

- 현재 1장 현장은 헤일로 수신망에서 출발·귀환하는 인스턴스다. 광산의 직접 운전 경로와 임의로 통합하지 않는다. 새 수로는 기존 1장 재방문 항목과 별도 출발 선택으로 제공한다.
- 2장 왜곡 경로는 짧은 표식 점검으로 검증 가능하게 만든다. 표식이 있는 경로는 안정되고, 불안정 구간은 반복 음향·조명 반응을 먼저 보여 준다. 무작위로 플레이어를 다른 곳에 보내지 않는다. 귀환이 항상 가능해야 한다.
- 3장 도시 단계는 `normal → uneasy → evacuation`, 4장 이후는 `recovery`로 확장한다. 고가·교통·주민 경로를 지형 변경과 함께 갱신하고 NPC가 소실 공간을 걷지 않게 한다. 다른 도시의 상태까지 일괄 초기화하지 않는다.
- 대피 지원 차량은 NPC 연출로 충분하다. 신규 탑승 시스템이나 우주선 조종은 필수 범위가 아니다.
- 4장 핵은 환경 장치다. 우주 밖 존재의 체력 바나 처치 보상을 만들지 않는다. 리아의 외부 역할은 예비 전원과 철수 절차가 있는 정상 작전으로 연출한다.
- 외부 소실은 지원팀의 확인과 리아의 철수 시작 이후 발생한다. 플레이어의 대사 읽기·전투 속도·선택 의뢰 완료율이 원인이 되어서는 안 된다.
- 4장 이후 리아를 `missing`으로 관리한다. 일반 중상의 60초 복귀와 구분하고 도시·광산·동행 장면에서 자동 재생성하지 않는다. 이전 광산 재방문도 현재 서사 상태를 읽어 리아를 표시하지 않아야 한다.

## 4. 선택 결과와 상태 계약

기존 소유 상태를 재사용한다. 기존 플래그와 같은 의미의 중복 bool을 만들지 않는다. 아래 점 표기 이름은 기획·저장용 키이며 구현이 완료된 멤버명이라는 뜻이 아니다.

| 기록 | 현행 대응 / 추가 요청 | 사용처 |
|---|---|---|
| `main.chapter1_complete`, `main.outer_waterway_unlocked` | `ChapterOneState.recordsCompared`, `waterwayUnlocked` | 2장 진입 |
| `side.mara_power_restored` | `GameState.isPowerRestored` | 3장 유도등. 마라에게 완료 보고한 `isSideQuestComplete`와 혼동 금지 |
| `side.portable_light_repaired` | `portableLightRepaired` | S20 귀환 표식·S50 조명 반응 |
| `side.convoy_vehicle_repaired` | `vehicleRepaired` | 대피 차량/도보 우회 분기 |
| `side.scrapper_detail_ledger_found` | `detailLedgerFound` | 예비 전원 창고·증언자 추적 |
| 2장 조사·과거·장막·문서 | 5절 기존 제안 플래그 + 신규 `main.chapter2_reported` | S21~25 완료 조건 |
| `choice.kain_response` | 미선택 / `understand` / `criticize` / `focus_present` | S22 선택·S51 후속 대사 |

| 대피 현장별 완료 | 집결로·부상자·통신을 각각 기록 | 부분 완료 저장·재개 |
| `main.missing_expedition_confirmed_alive` | 3개 증거 상호작용 완료를 함께 확인 | S35 생존 확인 |

| 에필로그 상태 | 복구 대화, 날짜 전환, `main.nereus_signal_received` | 17일 후 사건 1회 실행 |

선택 의뢰 완료 여부는 대피 방식·보존 자료·물자·후속 부탁을 바꾼다. 필수 인원 대피와 리아의 실종 여부를 숨겨진 점수로 바꾸지 않는다. 미완료 의뢰는 완료로 속여 처리하거나 조용히 삭제하지 말고 사건 이후의 새 목표를 연결한다. 이미 지급한 보상을 다시 주지 않는다.

## 5. 저장·중단 복귀와 의료 이송

2장 이후를 계속 개발하기 전에 버전이 있는 저장 형식을 마련한다. 현재 세션 메모리 상태를 영구 저장으로 표기하지 않는다.

- 퀘스트·지역 단계·선택·NPC 서사 상태·보유품·악명·플레이어 성장·이미 지급한 보상·안전 복귀 위치를 저장한다.
- 대화 중 저장은 장면 ID, 다음 미완료 대사, 미확정 선택, 실행 완료 이벤트를 포함한다. 대화 중 저장을 지원하지 않는 첫 버전은 명확히 알리고 안전한 장면 시작/종료 지점에 체크포인트를 둔다.
- 저장 버전이 다르거나 손상되었을 때 조용히 새 게임으로 덮어쓰지 않는다. 읽기 실패를 알리고 마지막 유효 저장을 보존한다.
- 의료 이송의 기존 레벨·크레딧·부품 패널티는 유지하되 조사·선택·실종·장 완료를 되돌리지 않는다. 현재 `HospitalRecovery`의 도시 귀환이 관문 내부 작전과 충돌하므로 **3장 진입 전 안전 거점 의료소와 작전 재개 출발점**을 먼저 마련한다.
- 핵을 이미 멈췄다면 의료소 복귀 후 다시 파괴하게 하지 않는다. 귀환 연출은 체크포인트에서 이어지고 확장 정지·소실을 1회만 실행한다.
- 저장·로드 뒤 주민과 동료는 안정된 ID로 복원한다. 광산의 무작위 구조 NPC 회차 ID와 메인 탐사대원 ID를 섞지 않는다.

## 6. 구현 우선순위와 완료 확인

1. **P0 — 읽기와 맥락:** R01~R04, 프롤로그 조사 기록, 1장 결론 대화 완료 처리. 실제 표시 폭·읽기 속도·E 입력 중복·전투 알림 우선순위 확인.
2. **P1 — 2장:** 저장 기반, 수로·두 조사 지점·고백·문서 대조·귀환·준비 구간. 두 조사 순서와 세 선택 조합이 같은 필수 결론에 도달하는지 확인.
3. **P2 — 3장:** 명시적 출발, 지역 단계·대피 분기·내부 진입·생존 확인. 선택 의뢰 미완료 상태에서도 필수 구조와 완료가 가능한지 확인.
4. **P3 — 4장·에필로그:** 3명 인수·동시 제어·핵 정지·외부 소실·복구·네레우스 신호. 실종 뒤 리아 재등장과 사건 중복 실행 방지 확인.

검증은 진행이 깨질 수 있는 경계와 선택 조합을 우선한다. 문장 자체를 그대로 복제한 테스트는 만들지 않는다.

| 확인 시나리오 | 기대 결과 |
|---|---|
| 광산 모든 단계에서 리아 재대화, 조사를 순서 밖에서 시도 | 현재 할 일만 안내. 완료 문양이 다시 선행 조사를 요구하지 않음 |
| 광산 조기 귀환·재입장·보고 후 재방문 | 조사 플래그 유지. 첫 입장 대사 반복과 자동 헤일로 귀환 오해 없음 |
| 1장 현장 6가지 순서, 발전기 조사만 한 상태, 장부 선확보 | 아직 하지 않은 조사 결과가 기록에 나오지 않음 |
| 1장 결론 대사를 천천히 읽기·E 길게 누르기 | 대사 미독 중 장 완료나 다음 지역 개방 없음. 보상 중복 없음 |
| 장면 중 전투·지도·정지·의료 이송·저장 복귀 | 대화 누락·공격 입력 잔류·NPC 순간 복제 없음 |
| 2장 두 조사 순서 × 카인 세 선택 | 중계실과 보고가 열림. 후속 대사만 달라짐 |
| S25에서 ‘아직 준비한다’, 실제 시간 장기 경과 | 재난·실종·주민 피해 자동 발생 없음 |
| 선택 의뢰 모두 미완료 / 모두 완료, 전원 우선순위 양쪽 | 필수 대피 가능. 방식과 복구 의뢰에 차이 |
| S35 생존 증거를 일부만 조사 | 생존 확인 결론·3장 완료가 아직 확정되지 않음 |
| 대원 인수 도중 중단·복귀 | 인수된 대원은 외부 유지. 남은 대원만 재개 |
| 핵 정지 전후 저장·의료 이송·재로드 | 핵 정지·도시 소실·리아 실종이 각각 1회 적용 |
| 4장 후 집·전망대·광산·1장 현장 재방문 | 리아의 기존 일상 모델·대사가 자동 재생성되지 않음 |
| S52 신호 후 단말 반복 조사·재로드 | 신호 최초 수신 1회. 음성 재청취와 이후 자유 플레이는 가능 |

현재 2장 진입을 막는 임시 ‘후속 지역 준비 중’ 문구는 수로 진입과 복귀가 실제로 연결된 시점에만 제거한다. 부분 완성 기능을 완료한 스토리처럼 안내하지 않는다.
