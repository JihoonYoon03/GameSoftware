# 튜토리얼 이동 구간과 격리 구역 콘텐츠 확장

## 모델 형태와 색상

| 구분 | 타입 | 형태의 차이 |
|---|---|---|
| 차량 | Coupe, Shuttle, Hauler, Patrol, JetBike | 승용 차체, 긴 셔틀, 화물 적재부, 경비 장비, 좌석과 핸들이 드러나는 개인용 바이크 |
| 캐릭터 | Explorer, Engineer, Guard, Medic, Researcher | 탐사 장비, 공구·정비 장비, 방호·무장, 의료 표식, 관측 장비 |
| 건물 | Habitat, Terraced, Workshop, Dome, Observatory | 경사 지붕 주거동, 층별 테라스, 공방, 돔, 큰 관측 돔과 관측 장비 |

타입은 형상을 정하고 Palette는 몸체(body)·장식(accent)·발광(emission) 색을 정한다.
동일한 타입에도 다른 팔레트를 지정할 수 있다. 생성된 형상은 기존 파일 캐시로 저장하고,
캐시 버전 3과 크기·체크섬 검증을 통과한 경우 다음 실행에서 읽어 사용한다.
약 238KiB인 라이브러리는 힙에 보관하며 생성·로딩·반환 중 스택 복사를 만들지 않는다.
차량·캐릭터·건물 생성 함수도 참조로 받은 저장 공간에 직접 채운다.
타입별 GPU 메시는 팔레트를 포함한 키로 구분한다.

차량의 기본 전방은 로컬 +X다. 헤드라이트는 앞쪽, 추진기 노즐은 뒤쪽에 있으며
불꽃은 노즐에서 로컬 -X로 뻗는다. 반대 방향 차량은 차체·노즐·헤드라이트·불꽃을 함께
반전한다. 추진기 셰이더는 emission 색을 사용하며, 주 불꽃 주변의 튀는 불꽃과
가속에 따른 길이 변화를 표현한다.

게임 실행 중 http://127.0.0.1:17707/models.html 에서 실제 모델 캐시의 15개 타입과
독립 색상 배치를 확인할 수 있다. 형태의 유한 좌표, 투영된 다각형의 볼록성,
노즐·헤드라이트의 앞뒤 배치는 데이터 검증 대상으로 포함한다.
브라우저의 형태 미리보기에는 실제 머터리얼·후처리·그림자·불꽃의 최종 합성이 포함되지 않는다.

수치 검토 결과: 차량·캐릭터·건물의 폴리곤/유리 면 214개에서 오목한 면이나 면적 0인 면은 없었다.
헤드라이트 중심 10개와 선 끝점 20개는 차체 면 내부/경계에, 추진기 앵커 10개는 노즐 면에 위치한다.
최대 파츠 수는 68개(용량 96개)다. 이 검토는 형상 데이터와 투영 좌표 검사이며 실제 렌더링 검증과는 별개다.

## 튜토리얼 진행

집 단말 확인 → 주거 구역에서 리아와 대화 → 전망대 진입 → 관측 단말에서 관문 신호 조사
→ 전망대 아래로 복귀 → 개인용 제트 오토바이와 E 상호작용 → 제트 주행 회랑 → 격리 구역.

전망대는 일반 주거동보다 큰 전용 외관과 관측실을 사용한다. 신호를 들은 상태와
튜토리얼 완료 상태는 별개다. 신호 조사 뒤 하강하고 오토바이 주행을 마친 시점에
튜토리얼이 완료된다. 마라의 전력 복구 선택 의뢰는 기존 상태로 이어진다.

제트 주행은 W·S 측면 조종, D 가속, A 감속, Space 부스트를 사용한다.
다층 배경의 시차 스크롤과 가까운 표식·잔해의 빠른 이동으로 속도 차이를 표현한다.
1800 거리의 회랑에서 붉은 장애물을 회피하며, 접촉하면 잠시 감속하고 계속 진행한다.
부스트는 소모 후 회복된다. 도착하면 바이크를 세우고 격리 구역의 도보 전투로 전환한다.
1 키는 격리 구역 콘텐츠의 빠른 시험 진입용이다.

## 격리 구역 팀 행동

64×64 맵과 NPC 20명, 적 정원 72기를 유지하며 4개의 팀 작업장을 배치한다.
팀의 공통 목적은 보급을 받고 손상 설비를 수리하는 것이다.

- 기술자는 담당 설비에 접근해 실제 수리 진행률을 올리고 보급품을 소비한다.
- 경비 인력은 작업장에 접근하는 실제 몬스터를 추적·공격·처치한다.
- 운송 인력은 중앙 집결지에서 작업장으로 실제 보급품을 운반한다.
- 의무 인력은 부상 팀원을 치료하며, 관측 인력은 조사와 수리 지원을 수행한다.
- 주민과 상인은 개인 성격과 기존 대화·거래 기능을 유지한다.

설비는 보급 대기·수리·위협·가동 상태를 가지며, 수리 완료 후 가동 유지와 다음 정비를
반복한다. 적은 팀원과 설비를 공격할 수 있다. NPC 체력이 소진되면 안전 구역에서 회복한다.
NPC의 몬스터 처치는 플레이어 경험치·처치 수와 별도로 집계한다.
이 행동은 현장 시험용 공동 작업이며 Concept.md의 메인 스토리 1~3장 전체 구현을 의미하지 않는다.

## 모니터 관측

http://127.0.0.1:17707/ 에서 전망대 장소·신호 조사·하강 상태, 제트 주행 진행률·속도,
팀 배정, 작업장 수리·내구도·재고, NPC 체력·교전 대상·처치 수를 확인한다.
수리·방어·보급·치료·관측·회복 행동을 필터로 선택할 수 있다.
지역을 떠나거나 일시정지하면 마지막 상태와 simulation_active=false를 함께 표시한다.
JSON 원본과 상세 데이터 의미는 Game_Monitoring.md를 참고한다.

## 확인 범위와 사용자 확인 순서

이 변경에서는 소스 연결·자료형·상태 분기·브라우저 스크립트 구문을 정적으로 확인한다.
빌드, 게임 실행, 실제 렌더링 및 브라우저 화면의 결과 확인은 사용자가 수행한다.

1. 새 빌드에서 모델 캐시 버전 전환 후 15종 카탈로그가 로드되는지 확인한다.
2. 도시 차량의 전후 방향마다 헤드라이트·추진기 위치, 뒤로 나오는 불꽃, 발광색 일치를 확인한다.
3. 같은 타입의 다른 색과 차량·캐릭터·건물의 각 타입별 실루엣을 확인한다.
4. 큰 전망대 외관·진입 위치·관측 단말·하강 상호작용을 순서대로 확인한다.
5. 하강 후 바이크 탑승, W·S 조종, D·A 속도 변화, 부스트, 장애물 회피·접촉을 확인한다.
6. 일시정지·초기화·도시 귀환 후 단계가 섞이지 않는지 확인한다.
7. 격리 구역에서 4개 팀의 보급·수리·방어, 몹과 설비의 실제 체력 변화를 관찰한다.
8. 의무 인력의 치료와 부상 NPC 회복, 리아·카인의 동행 토글을 확인한다.
9. 모니터의 팀·작업장·주행 상태와 게임 화면이 일치하고 NPC 처치가 플레이어 경험치를 올리지 않는지 확인한다.
10. 기존 프로파일러의 FPS·드로우 콜·NPC 갱신·길 찾기·JSON 생성 비용을 확인한다.

협업 프로파일링에는 npc_cooperation, npc_shots, npc_enemy_kills,
workstation_repair_completions, workstation_supply_deliveries, npc_rescues 항목을 추가했다.

### 확인한 내용

- 생성 모델의 폴리곤/유리 면 214개, 조명·노즐 장착점과 부품 수를 수치 검토했다.
- 퀘스트 지점 접근 좌표, 전환 분기, 호출 인터페이스, 프로젝트 파일 등록을 정적으로 확인했다.
- 브라우저 JavaScript 구문, HTML 연결, JSON 필드와 프로파일러 항목 연결을 확인했다.
- 검토 중 발견한 면적 0 차량 후면, 차체 밖 헤드라이트, 액세서리만 표시되는 탑승자,
  텍스트 자원이 포함된 바닥 캐시, NPC 초기 행동 대상 좌표 문제를 소스에서 수정했다.
- 이 내용은 실제 게임 렌더링·플레이 검증이나 60FPS 달성 확인을 의미하지 않는다.

### 사용자 보고 오류와 수정 상태

사용자가 SimpleGame.exe의 0xC00000FD(Stack overflow) 예외를 보고했다.
약 238KiB 모델 라이브러리를 지역 변수와 값 반환으로 중복 복사하는 경로를 확인해 수정했다.

- 라이브러리는 std::unique_ptr로 힙에 보관한다.
- Generate/GenerateVehicle/GenerateCharacter/GenerateBuilding은 저장 공간에 직접 생성한다.
- 캐시 로딩·저장은 실제 Library 크기를 사용하며 기존 버전 3 형식은 유지한다.
- 손상된 캐시를 읽은 뒤 재생성할 때는 새 저장 공간을 사용한다.

상태: 수정 적용 및 소스 확인 완료, 재빌드·재실행으로 오류가 해소되었는지는 확인 대기.
예외 주소만으로 실제 발생 호출 경로를 확정한 것은 아니며, 재발 시 디버거 호출 스택을 확인한다.

### 다음 확인 순서

1. 사용자 재빌드 후 시작 및 모델 캐시 로딩/생성이 정상인지, 스택 오버플로가 재발하는지 확인.
2. 차량·캐릭터·건물 5종과 전후 장착점·불꽃 색/방향을 실제 렌더링에서 확인.
3. 전망대 진입 → 측정 → 하강 → 바이크 → 격리 구역의 전체 흐름 및 일시정지·초기화를 확인.
4. NPC의 보급·수리·방어·치료, 몹 재출현, 플레이어 경험치 분리와 모니터 일치를 확인.
5. 프로파일링 로그로 FPS·드로우 콜·협업·길 찾기·JSON 생성 비용을 확인.

빌드와 실행 결과 확인은 특별한 상황이 아니면 사용자가 직접 진행한다.
현재 변경에는 수정 파일과 신규 미추적 파일이 있으며, 이 기록 요청에서는 커밋을 수행하지 않았다.
