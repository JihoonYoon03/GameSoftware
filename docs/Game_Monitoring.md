# 로컬 게임 모니터

## 사용

1. 프로젝트를 빌드한다. HTML/CSS/JS가 실행 파일 옆의 Monitor 폴더로 자동 복사된다.
2. 게임을 실행한다. 콘솔의 [Monitor] 주소를 확인한다.
3. 별도의 브라우저 창에서 http://127.0.0.1:17707/ 를 연다.
4. 게임에서 1 키로 격리 구역에 바로 진입할 수 있다.
5. NPC 이름을 선택하면 목적지, 행동 패턴, 동행 설정, 남은 경로, 치료 대기 등이 표시된다.

화면의 '새 창으로 열기' 버튼으로 독립 브라우저 창을 열 수 있다.
별도의 서버 프로그램, 패키지 설치, 인터넷 연결은 필요하지 않다.
HTML 파일을 직접 더블 클릭한 경우 서버 주소로 접속하라는 안내가 표시된다.
게임 실행 중에만 JSON API가 응답한다.

## 통신

- 게임 내 서버: Windows Winsock, 127.0.0.1:17707 에만 바인딩.
- HTML: / 또는 /index.html. 정적 파일: /app.js, /style.css.
- 상태 API: GET /api/state → application/json; charset=utf-8.
- 전송 방식: HTTP JSON 폴링. 게임은 500ms마다 최신 스냅샷을 생성한다.
- 브라우저는 응답 완료 후 약 500ms에 다음 요청을 시작한다. 중첩 요청은 하지 않는다.
- 요청 제한 시간 2초, 실패 시 1~10초 간격 자동 재접속.
- 정상 응답이어도 sequence가 3초 이상 바뀌지 않으면 '상태 갱신 지연' 표시.
- 게임 일시정지 중에도 스냅샷 생성과 통신을 유지한다.
- 새 게임 실행은 session_id로 구분한다. 초기화는 같은 세션에서 계속 관측한다.
- 게임 종료 시 통신 스레드와 소켓을 정리한다.
- 게임 재실행 후 재접속하면 기존 브라우저에서 다시 관측할 수 있다.

웹 화면은 서버와 같은 출처에서 JSON을 수신한다. 임의의 파일 경로를 제공하지 않으며
게임 상태를 변경하는 명령은 지원하지 않는다.
최대 동시 연결 16개, 요청 헤더 최대 4KiB, 클라이언트 연결 수명 3초로 제한한다.
느린 브라우저 전송은 별도 통신 스레드에서 비동기 소켓으로 처리한다.
게임의 가변 상태는 게임 스레드에서만 읽고, 통신 스레드에는 완성된 JSON 문자열을 전달한다.
하나의 최신 스냅샷만 유지하므로 브라우저 미접속 시 전송 대기열이 쌓이지 않는다.

## 데이터

스키마: game_monitor_v1. 모든 화면 문자열은 한글, JSON 키는 영어 snake_case.

| 필드 | 내용 |
|---|---|
| session_id, sequence | 실행 구분, 스냅샷 순번 |
| sent_at_unix_ms | 생성 시각 (Unix 밀리초) |
| paused, current_region_id, current_area | 게임 상태와 현재 지역 |
| counts | 전체/현재 지역/AI 갱신 NPC, 전체/생존/재출현 몹, 드롭 수 |
| regions[] | 마을·거점의 인구, 분위기, 성향, 전력, 관문 신호, 소문, 몹 수 |
| npcs[] | 배치 ID, 이름, 역할, 성격, 패턴, 행동, 동행, 위치·목적지·경로·대기시간 |
| mobs[] | 배치 ID, 지역, 위치, 체력, 생존 여부, 재출현 시간 |
| player | 위치, 레벨, 경험치, 체력, 능력치, 보유품, 처치 수 |
| quests | 현재 구현된 튜토리얼·전력·성장 목표 상태 |
| performance | 기존 game_performance_v1의 최근 완료된 계측 구간, 첫 구간 전에는 null |
| transport | 통신 방식, HTTP 요청 수 |
| notice | 게임 내 현재 안내 문구 |

배치 ID는 현재 실행/맵의 배치 식별자다. 맵 재생성 시 같은 ID를 다시 사용할 수 있다.
프로그램을 종료하면 대시보드의 변경 이력은 저장되지 않는다.
JSON 저장 버튼으로 현재 스냅샷을 파일로 내려받을 수 있다.

## 현재 월드의 해석

- 마을/거점: 헤일로 주거 구역 07, 관문 외곽 격리 구역 집결지.
- population_source=placed_npcs: 화면에 배치한 NPC 수이며 세계관상 전체 도시 인구가 아니다.
- 헤일로: 주민 12명 + 리아·마라 2명. 현재 AI 없이 정적 배치이므로 simulation_active=false.
- 격리 구역: 진입 후 NPC 20명, 몹 정원 72기. 진입 전에는 생성되지 않아 0으로 표시한다.
- 격리 구역을 떠나면 마지막 상태를 유지한다. AI·재출현 시간은 현재 게임 동작대로 중지된다.
- 따라서 두 지역 생성 후 전체 NPC는 34명, 격리 구역의 현재 지역 NPC는 20명이다.
- 헤일로와 격리 구역의 리아·마라는 별도의 테스트 배치이므로 각각 집계된다.
- personality=null: 기존 NPC에 성격 데이터가 정의되지 않은 경우. UI에는 '미설정'을 표시한다.
- 동행 설정과 실제 행동을 분리한다. 위험 회피 중에도 동행 설정이 켜져 있을 수 있다.
- 분위기는 퀘스트 플래그/NPC 활동에서 도출한다. mood_source에 근거를 남긴다.
- 성향은 지역 설정 설명이다. disposition_source=authored_context.
- 소문은 주민·테스트 NPC 설정 대사에서 발췌한 정보다. 소문 전파 시뮬레이션은 현재 없다.
- 소문의 confirmed=false는 확인되지 않은 주장이다. 코스믹 호러 현상의 원인을 확정하지 않는다.
- 일부 NPC dialogue는 상시 참고 대사이며 게임의 모든 조건부 대화 분기를 재현하지 않는다.

## 성능과 확장

게임은 0.5초마다 JSON을 생성한다. 생성 비용은 cpu_scopes_ms.monitor_snapshot,
생성 횟수는 counters.monitor_snapshots로 기존 프로파일링과 함께 기록한다.
네트워크 요청 수는 transport.requests_served에서 확인한다.
대시보드 변경 기록은 수신한 연속 스냅샷을 비교하여 최대 100건 유지한다.
500ms 사이에 시작하고 끝난 짧은 행동은 관측되지 않을 수 있다.
NPC/몹 데이터가 크게 늘어나면 지역 구독, 증분 전송 등의 추가 최적화가 필요하다.

소스 책임:

- Monitoring/GameMonitor.cpp: 시작·종료, 발행 주기와 계측.
- Monitoring/WorldSnapshot.cpp: 기존 게임 데이터 → JSON.
- Monitoring/LocalMonitorServer.cpp: 로컬 HTTP, 정적 파일, 최신 JSON 전달.
- monitor/index.html, style.css, app.js: 브라우저 화면과 수신.
- Profiler.cpp: 최근 성능 구간 JSON 제공.

새 마을을 추가할 때 regions[]에 상태와 출처를 넣고 npcs[].region_id로 연결한다.
브라우저의 마을 카드와 지역 선택 목록은 regions[]에서 생성된다.
포트를 변경하려면 GameMonitor.cpp의 kPort와 사용 안내 주소를 함께 수정한다.

## 사용자 확인 순서

이 작업에서는 게임 빌드·실행과 브라우저 화면 결과 확인을 수행하지 않았다.

1. 새 빌드의 실행 폴더에 Monitor/index.html, app.js, style.css가 있는지 확인.
2. 게임 실행 후 URL 접속, 초기 헤일로 14명 / 격리 구역 미생성 확인.
3. 1 키 진입 후 전체 NPC 34명 / 격리 구역 20명 / 몹 72기 확인.
4. NPC 검색·필터·상세, 동행 토글과 위치/경로 변화를 확인.
5. 몹 처치·재출현, 치료 대기, 경험치와 부품 변경이 반영되는지 확인.
6. 일시정지 중 AI 갱신 중지와 모니터 연결 유지 확인.
7. 도시 귀환 시 격리 구역 상태를 보관 상태로 표시하는지 확인.
8. 게임 종료 시 연결 끊김, 재실행 시 자동 연결 복구 확인.
9. JSON 저장과 원본 JSON 보기, FPS·드로우 콜·JSON 생성 시간 확인.

접속 실패 시:

- 콘솔에 포트 사용 오류: 이미 실행 중인 게임 등 17707 사용 프로그램을 종료하고 재실행.
- asset missing or invalid: 정상 빌드 후 실행 폴더의 Monitor 파일 복사 여부 확인.
- 런타임 파일을 별도로 옮겼다면 Monitor 폴더도 함께 옮긴다.
- 이 서버가 시작되지 않아도 기존 게임 진행은 계속된다.
